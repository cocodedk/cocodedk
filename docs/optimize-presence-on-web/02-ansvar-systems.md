## SEO strategy

- **Open-source as SEO:** the MCP server appears on at least 4 third-party MCP registries (mcpservers.org, lobehub.com, pulsemcp.com, mcp.aibase.com), each generating a backlink and a page indexed for `EU compliance MCP` queries
- README quality: positions clearly — *"EU compliance is scattered across EUR-Lex PDFs"* — problem-led
- Example queries baked into README (e.g. *"Does the EU AI Act apply to my recruitment screening tool?"*) — these are exactly the search intents future customers will type
- Cross-regulation comparison as a feature — owns the keyword space for "DORA vs NIS2," "GDPR vs AI Act," etc.

## Key takeaways

- ✓ **What they do exceptionally well:** *productize the expertise as open source*. Each MCP server is simultaneously: (a) a useful tool, (b) a SEO asset on multiple registries, (c) a credibility artefact, (d) a sales lead-gen surface.
- ✗ **What they miss:** Stockholm, not Copenhagen — the DK SME market still has room for a DK-native equivalent.
- **Critical replication moves for cocode.dk:**
  1. **Build and publish 1–2 MCP servers** that match Babak's expertise (e.g. `cocode-dk/dk-grc-mcp` covering DK-specific guidance: NIS2 transposition, D-mærket, AFM/Datatilsynet rulings) — a niche too small for Ansvar to chase.
  2. **List on every MCP registry** the moment it's published (mcpservers.org, lobehub, pulsemcp, mcp.aibase, smithery.ai).
  3. **Mirror the README playbook** — lead with the problem, not the product. Bake example queries into the README that match real search intent.
